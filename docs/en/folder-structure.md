# Folder structure

The project structure rests on one rule: **generated files are kept apart from hand-written ones.** Anything produced by a tool also says at the top of the file that it must not be edited by hand.

```text
novaadmin/
├── index.html                     product page (landing)
├── vite.config.js                 entries, aliases, chunks and project plugins
├── package.json                   scripts and version-locked dependencies
├── public/                        assets copied without processing
│   ├── assets/{logo,logo-mark,favicon}.svg
│   ├── assets/img/{avatars,products,brands}/
│   ├── site.webmanifest
│   ├── robots.txt                 generated by gen-nav
│   └── sitemap.xml                generated by gen-nav
├── src/
│   ├── pages/**                   206 generated pages (shell + content placeholder)
│   ├── partials/                  shared fragments
│   │   ├── head.html              meta, fonts, stylesheet link
│   │   ├── header.html            app header (search, notifications, profile)
│   │   ├── overlays.html          command palette, shortcuts, toast host
│   │   ├── customizer.html        appearance customizer drawer
│   │   ├── footer.html            footer
│   │   ├── scripts.html           JS entry
│   │   ├── docs/*.html            documentation bodies (generated from docs/ by gen-docs)
│   │   └── pages/<path>.html      manual override of a page body (optional)
│   ├── scss/
│   │   ├── main.scss              exact import order
│   │   ├── base/                  tokens, palettes, themes, reset, fonts, Bootstrap bridge
│   │   ├── layout/                shell, sidebar, header, page head, docs, auth
│   │   ├── components/            28 component files (button, form, card, table, kanban…)
│   │   ├── pages/                 page compositions (landing, invoice, dashboard)
│   │   └── utilities/             helper classes that come last
│   ├── js/
│   │   ├── main.js                bootstrapper: theme → layout → shell → page route
│   │   ├── core/                  20 core modules (no dependency on a specific page)
│   │   └── pages/                 one controller per area, lazy-loaded
│   ├── services/                  data layer with a REST contract
│   ├── data/                      realistic sample data
│   ├── locales/                   fa/en/ar dictionaries + generated data
│   └── config/config.js           brand settings, defaults, currency, time zone
├── docs/                          23 Markdown documentation sources (+ translations in en/ and ar/)
└── tools/
    ├── manifest.mjs               single source of navigation and the page list
    ├── build-pages.mjs            generates pages + locale data
    ├── gen-assets.mjs             generates logo, avatar, product and brand SVGs
    ├── gen-nav.mjs                navigation.js + sitemap + robots
    ├── gen-docs.mjs               Markdown → documentation bodies
    ├── flatten-dist.mjs           final output tidy-up
    ├── qa-links.mjs               output quality control
    ├── smoke.mjs                  runs controllers in a simulated DOM
    ├── package.mjs                builds the final package
    └── nova-plugin.mjs            Vite plugin (include, tokens, clean paths)
```

## Important rules

- **Do not edit `src/pages/**`.** It is rewritten on every build. To change a page body, create a file with the same name in `src/partials/pages/`.
- **`src/locales/generated.js` and `src/data/navigation.js` are generated.** Their sources are `tools/manifest.mjs` and `docs/`.
- **Assets in `public/` are copied without processing.** If you want Vite to optimise an image, import it from `src/`.
- **Everything in `src/` is shipped to the browser;** do not put tool or documentation files there.

## Core module map

| Module | Responsibility |
| --- | --- |
| `dom.js` | Selectors, rendering, events, class helpers |
| `theme.js` | Theme, palette, layout, density, font size, sidebar style |
| `layout.js` | Shell, sidebar, mobile mode, two-column layout |
| `chrome.js` | Command palette, shortcuts, notifications, widget editor, customizer |
| `datatable.js` | Full data table (search, filter, sort, columns, selection, export) |
| `charts.js` | A single ApexCharts skin for light/dark mode |
| `calendar.js` / `jalali.js` | Month/week/day/list calendar and Jalali date conversion |
| `kanban.js` | Drag-and-drop board with SortableJS and saved order |
| `i18n.js` | Active language, `data-i18n`, direction and text rearrangement |
| `numbers.js` | Persian/Arabic/Latin digits, currency format, compact numbers |
| `toast.js` / `modal.js` | Toasts in four positions and confirmation dialogs |
| `form.js` / `ui.js` | Validation, form states, tabs, accordion, printing |

> Tip: the boot order in `main.js` matters: `i18n → theme → layout → dropdowns → chrome → forms → ui → route()`. If a module needs DOM produced by a controller, it must be called after `route()`.
